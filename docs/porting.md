# 用别的工具怎么落地这五步

> ⚠️ **先说清**：**下面的"宿主怎么挂"部分是「形态描述」，不是 API 文档。**
> 各个工具的钩子名字、参数、返回值都会变 —— **请以你手上那份官方文档为准。**
> **而「五步」那部分是方法，它不依赖任何工具的 API。**

---

## 一、这五步真正依赖的只有一个东西：**一个"动手前"的钩子**

整套东西挂在一处：

```
你/AI 要调用某个工具（写文件、跑命令）
        ↓
   ★ 这里有一个"还能拦下来"的时刻 ★
        ↓
   有规则命中？
   ├─ 是 → 阻止 + 说清"为什么"和"怎么改"
   └─ 否 → 放行
```

**各家工具把这个时刻叫什么、怎么注册，各不相同**；但**它们都有** ——
因为"**在工具调用前看一眼**"是任何 agent 宿主都绕不开的一环。

**⭐ 而这里有个判据**：**如果你用的工具根本没有这个时刻** ——
**那这五步里"拦"这一步就落不了地**，你只能做"记 → 归类 → 升格"（**而那三步仍然有价值**：
**它们把"踩过的坑"变成一个能查的东西**）。

---

## 二、几个已知的落点（**形态描述，细节请查官方文档**）

| 宿主 | 那个时刻大概叫什么 | 备注 |
|---|---|---|
| **DSH** | **工具守卫**（这个项目的实现就是它） | 守卫是**同步**的：返回一段文本 = 拒绝，返回空 = 放行 |
| **Claude Code** | **`PreToolUse` 类钩子** | 有一个"工具调用前"的钩子；**它被用来做事前检查是有先例的**（我们在做 prior art 调研时见过把护栏挂在那里的项目） |
| **Codex / 其它** | **看它有没有"工具调用前"的拦截点** | 没有的话，退化成"只记不拦" |

**⚠️ 而三个实现细节，每个都会咬你一口**：

1. **守卫多半是同步的** —— **你不能在里面 await 一个慢操作**。
   （所以我们把"慢的那部分"放到会话启动时的后台任务里，只在守卫里做**能在几毫秒内判完**的事。）
2. **守卫的返回值形状各家不同** —— **别照抄**，看清你这家的：什么叫"拒绝"、什么叫"提示"、能不能附带一段发给模型的说明。
3. **⚠️ 而"能不能附带说明"决定成败** ——
   **只说"不行"的护栏，比没有护栏更让人烦**（因为你还得自己去猜为什么）。

## 三、五步在各家怎么落

**这五步和宿主无关** —— 它们只需要"能存文件"（甚至只需要能写文本）：

| 步 | 做什么 | 和宿主有没有关系 |
|---|---|---|
| **1 踩** | 出错 / 被纠正 / 自己发现不对 | 无关 |
| **2 记** | 往一个**只进的池子**里写一条（它是什么 / 症状 / 证据 / 什么情况下会犯 / 谁发现的） | **有关**：最好能在会话里直接记（`guardrail_report` 那种），**但纯脚本也行**（这个项目里两条都有） |
| **3 归类** | 把它归进"已有的某一组"，或"新开一组"，或"判定不进清单" | **无关** —— 那是一个人拍板的动作；**但"展开 + 找最近邻"要脚本** |
| **4 升格** | 判据能写 → 写成一条规则；写不了 → 明确说"拦不住" | **有关**：规则要挂到那个钩子上 |
| **5 拦** | 命中就说清"为什么 + 怎么改 + 这条规则的战绩" | **有关**：就是上面那个时刻 |

**⭐ 而"拦"那一步的文案里有一件事不能省**：
**告诉它「这条规则到今天拦过几次」** ——
**因为被拦的人（或 AI）需要知道"这是偶发还是老毛病"**，
**而那决定了它该"改这一次"还是"改那个习惯"。**

---

## 四、如果你只做一件事，做这个

**别先写规则。先写"记"。**

理由：
- **规则的收益是"少踩一次"**，而那**很难度量**
- **"记"的收益是"你终于知道自己在哪类事上反复栽"**，而那**一眼就能看出来**
- **而更重要的是**：**没有"记"这一步，"升格"就没有原料** ——
  **你会开始凭印象写规则，而凭印象写的规则，判据多半是错的。**

> **我们真的犯过**：凭印象给一条规则写了个判据（"命令里同时含 A 和 B"）——
> **而它拦的是"命令里有那些词"，和它声称要管的事毫无关系。**
> **那条判据在清单里挂了很久，直到有人问「它到底抓的是什么」。**

## 五、这个项目里"和宿主无关"的那些东西

**你可以直接拿走思路**（代码不一定能直接搬，但形状可以）：

| 东西 | 它在解决什么 |
|---|---|
| **规则表 / 阈值表做成数据文件** | **改规则不用改代码、不用重启**；而"坏数据 → 回落默认"保证它**不会因为数据坏了就不设防** |
| **每条规则带"战绩"**（拦过几次 / 提示过几次 / 被申辩过几次） | 让人能判断"这条还值不值得留" |
| **申辩出口**（认为误报 → 申诉 → 进画像） | **让"规则错了"有一条正规的路** —— 否则人会去绕它 |
| **熔断**（连拒 N 次放行） | **绝不用"无限拦"惩罚"诚实报告卡住"的人** |
| **"跳过"必须带原因，且总数必须打印** | 否则「**0 个问题**」和「**根本没查**」长得一样 |
| **每条提醒都带一个数，归零就静默** | 否则就是墙纸 |
